The Cortex CLI drives **Cortex Code** from a terminal. It uses the same account as the web app. It does not run the model on your laptop.

</Frame>

## 1. Install

### Linux and macOS

The installer downloads the matching archive from [software.cortex.foundation](https://software.cortex.foundation), verifies its SHA-256, and installs to `~/.local/bin`.

```bash
curl -fsSL https://software.cortex.foundation/install.sh | sh
```

Read it first if you prefer:

```bash
curl -fsSL https://software.cortex.foundation/install.sh | less
```

### Windows

Windows installs into `%LOCALAPPDATA%\Cortex\bin` after the same checksum check:

```powershell
irm https://software.cortex.foundation/install.ps1 | iex
```

### Check it worked

```bash
cortex --version
```

Update later with `cortex upgrade`.

## 2. Sign in when it asks

Sign in from the CLI when it asks — it uses the same Cortex account as the web app. This site does not document the sign-in protocol.

## 3. Start a session

```bash
cd ~/code/my-project
cortex
```

<Frame>
  <img src="/images/cli/intro.gif" alt="Cortex CLI on a macOS desktop: splash, prompt, slash commands, and a Shell tool row" />
</Frame>

Type what you want changed and press Enter. The timeline shows files read, edits, and commands as they happen.

```
> add a health check endpoint and cover it with a test
```

## 4. What the CLI is — and is not

| The CLI does | The CLI does not |
| --- | --- |
| Drive Code sessions | Run the model on your laptop |
| Work in a project directory | Replace web Chat |
| Offer This PC and SSH | Run those hosts in the browser |

Web Cortex Code stays Cloud-only. This PC and SSH are desktop-app and CLI surfaces. How sessions work: [Code](/code) and [CLI for Code](/code/cli).
