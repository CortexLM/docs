# Creating Custom Agents

Agents are specialized AI assistants with custom system prompts, tool restrictions, and behavior configurations. This guide covers everything you need to create powerful custom agents.

## Why Custom Agents?

## Quick Start

### Create Your First Agent

```bash
# Interactive creation
cortex agent create

# Or with AI generation
cortex agent create --generate "A Python expert focused on clean code and testing"
```

### Use Your Agent

```bash
# In CLI
cortex --agent my-agent "task"

# Or in TUI
/agent my-agent
```

## Agent File Format

Agents are Markdown files with YAML frontmatter:

```markdown
---
name: security-auditor
description: "Security-focused code reviewer"
mode: subagent
temperature: 0.2
allowed_tools:
  - Read
  - Grep
  - Glob
denied_tools:
  - Execute
  - Create
  - Edit
max_turns: 10
can_delegate: false
color: "#EF4444"
tags:
  - security
  - review
---

You are a security expert reviewing code for vulnerabilities.

## Your Expertise
- OWASP Top 10 vulnerabilities
- Secure coding practices
- Authentication and authorization
- Data protection and encryption
- Input validation and sanitization

## Review Process
1. Identify potential security issues
2. Classify by severity (Critical/High/Medium/Low)
3. Explain the vulnerability
4. Provide remediation steps

## Output Format
For each issue found:
- **Severity**: Critical/High/Medium/Low
- **Location**: File and line number
- **Issue**: Description of the vulnerability
- **Risk**: Potential impact if exploited
- **Fix**: Recommended remediation
```

## Configuration Options

### Basic Settings

| Option | Type | Description |
|--------|------|-------------|
| `name` | string | Unique identifier (required) |
| `description` | string | What the agent does |
| `mode` | string | `primary`, `subagent`, or `all` |

### Model Settings

| Option | Type | Description | Range |
|--------|------|-------------|-------|
| `model` | string | Model override | |
| `temperature` | float | Creativity | 0.0-2.0 |
| `top_p` | float | Sampling | 0.0-1.0 |
| `max_tokens` | int | Response length | |

### Tool Control

| Option | Type | Description |
|--------|------|-------------|
| `allowed_tools` | list | Only these tools available |
| `denied_tools` | list | These tools blocked |

### Behavior

| Option | Type | Description | Default |
|--------|------|-------------|---------|
| `can_delegate` | bool | Can spawn subagents | `true` |
| `max_turns` | int | Maximum turns | |
| `hidden` | bool | Hide from listings | `false` |

### Display

| Option | Type | Description |
|--------|------|-------------|
| `display_name` | string | Name shown in UI |
| `color` | string | Hex color for UI |
| `tags` | list | Categories |

## Agent Modes

### Primary Agents

User-facing agents shown in the agent picker:

```yaml
mode: primary
```

Use for:
- General-purpose coding assistants
- Domain experts (Rust, Python, etc.)
- Workflow-specific agents (PR review, docs)

### Subagents

Agents invoked by other agents:

```yaml
mode: subagent
```

Use for:
- Specialized tasks (code search, testing)
- Delegation targets
- Parallel task execution

### All Mode

Available as both:

```yaml
mode: all
```

## Tool Restrictions

### Allow List (Safest)

Only specified tools available:

```yaml
allowed_tools:
  - Read
  - Grep
  - Glob
  - LS
```

### Deny List

Block specific dangerous tools:

```yaml
denied_tools:
  - Execute
  - Create
  - Edit
```

### Available Tools

| Tool | Description | Risk Level |
|------|-------------|------------|
| `Read` | Read files | Low |
| `Grep` | Search contents | Low |
| `Glob` | Find files | Low |
| `LS` | List directories | Low |
| `Create` | Create files | Medium |
| `Edit` | Modify files | Medium |
| `MultiEdit` | Batch edits | Medium |
| `Execute` | Run commands | High |
| `FetchUrl` | HTTP requests | Medium |
| `WebSearch` | Web search | Low |
| `TodoWrite` | Task tracking | Low |
| `Task` | Spawn subagents | Medium |

## Example Agents

### Documentation Writer

```markdown
---
name: docs-writer
description: "Technical documentation specialist"
mode: primary
temperature: 0.5
model: gpt-4o
allowed_tools:
  - Read
  - Grep
  - Glob
  - Create
  - Edit
denied_tools:
  - Execute
color: "#3B82F6"
---

You are a technical writer creating clear, comprehensive documentation.

## Guidelines
- Write for the target audience (developers, users, etc.)
- Use clear, concise language
- Include practical examples
- Add cross-references and links
- Follow the project's documentation style

## Structure
1. Overview/Introduction
2. Installation/Setup
3. Usage Examples
4. API Reference
5. Troubleshooting

## Style
- Use active voice
- Be specific and precise
- Include code examples with comments
- Add diagrams where helpful
```

### Test Generator

```markdown
---
name: test-generator
description: "Generates comprehensive test suites"
mode: subagent
temperature: 0.3
allowed_tools:
  - Read
  - Grep
  - Glob
  - Create
  - Edit
max_turns: 15
color: "#10B981"
---

You are a testing expert creating comprehensive test suites.

## Coverage Goals
- Unit tests for all public functions
- Integration tests for key workflows
- Edge cases and error handling
- Performance-sensitive paths

## Test Patterns
- Arrange-Act-Assert
- Given-When-Then
- Table-driven tests
- Property-based testing

## Quality Checks
- Tests are independent
- Clear test names
- Good assertion messages
- No flaky tests
```

### Code Reviewer

```markdown
---
name: code-reviewer
description: "Thorough code review with actionable feedback"
mode: subagent
temperature: 0.2
allowed_tools:
  - Read
  - Grep
  - Glob
denied_tools:
  - Execute
  - Create
  - Edit
max_turns: 5
color: "#F59E0B"
---

You are a senior engineer conducting code reviews.

## Review Checklist
1. **Correctness**: Does it work as intended?
2. **Security**: Any vulnerabilities?
3. **Performance**: Efficient algorithms and data structures?
4. **Readability**: Clear and maintainable?
5. **Testing**: Adequate test coverage?

## Feedback Style
- Be constructive and specific
- Explain the "why" behind suggestions
- Provide code examples when helpful
- Prioritize issues by importance

## Output Format
### Critical Issues
(Must fix before merge)

### Suggestions
(Improvements to consider)

### Praise
(What's done well)
```

## Agent Locations

| Location | Priority | Scope |
|----------|----------|-------|
| `.agents/` | 1 | Project (agent.md compatible) |
| `.agent/` | 2 | Project (agent.md compatible) |
| `.cortex/agents/` | 3 | Project |
| `~/.cortex/agents/` | 4 | Personal |

Project agents override personal agents with the same name.

## Best Practices

<AccordionGroup>
  <Accordion title="Start Restrictive">
    Begin with minimal tools and add as needed:
    ```yaml
    allowed_tools:
      - Read
      - Grep
    ```
  </Accordion>
  
  <Accordion title="Set Temperature Appropriately">
    - **0.0-0.3**: Precise tasks (review, analysis)
    - **0.3-0.7**: General coding
    - **0.7-1.0**: Creative tasks
  </Accordion>
  
  <Accordion title="Use Subagents for Delegation">
    Create focused subagents for specific tasks:
    ```yaml
    mode: subagent
    description: "Use when analyzing test coverage"
    ```
  </Accordion>
  
  <Accordion title="Document the Agent">
    Include clear instructions in the system prompt about:
    - When to use this agent
    - Expected output format
    - Limitations
  </Accordion>
</AccordionGroup>
