# Custom Commands

Custom commands let you define reusable prompts for common tasks. Execute them with a single slash command.

## Quick Start

Create a command file in `.cortex/commands/`:

```markdown
---
description: "Run tests with coverage"
agent: build
---

Run the full test suite with coverage report.
Focus on failing tests and suggest fixes.
```

Use it:
```
/test
```

## Creating Commands

### File-Based Commands

Create Markdown files in:
- **Project**: `.cortex/commands/`
- **Personal**: `~/.cortex/commands/`

The filename becomes the command name:
- `test.md` → `/test`
- `review.md` → `/review`

### Config-Based Commands

Add to `config.toml`:

```toml
[commands.test]
template = "Run tests with coverage and report failures"
description = "Run test suite"
agent = "build"
model = "claude-sonnet-4"
```

## Command Format

### Frontmatter

```yaml
---
description: "What this command does"
agent: build
model: claude-sonnet-4
subtask: false
---
```

| Option | Description |
|--------|-------------|
| `description` | Shown in command list |
| `agent` | Agent to use |
| `model` | Model override |
| `subtask` | Force subagent execution |

### Template

The body is the prompt template:

```markdown
---
description: "Create a new component"
---

Create a new React component named $ARGUMENTS with TypeScript support.
Include proper typing and a basic test file.
```

## Placeholders

### Arguments

| Placeholder | Description |
|-------------|-------------|
| `$ARGUMENTS` | All arguments |
| `$1`, `$2`, ... | Positional arguments |

Example:
```markdown
---
description: "Create component"
---

Create a React component named $1 in $2 directory.
```

Usage:
```
/component Button src/components
```

### Shell Output

Include command output with `` !`command` ``:

```markdown
---
description: "Analyze test coverage"
---

Here are the test results:
!`npm test`

Analyze failures and suggest fixes.
```

### File References

Include files with `@path`:

```markdown
---
description: "Review component"
---

Review @src/components/Button.tsx for best practices.
```

## Example Commands

### Test Runner

```markdown
---
description: "Run tests and fix failures"
agent: build
---

Run the test suite:
!`npm test`

If there are failures:
1. Analyze the error messages
2. Identify the root cause
3. Fix the issues
4. Re-run to verify
```

### PR Description Generator

```markdown
---
description: "Generate PR description"
---

Generate a pull request description for these changes:

!`git diff main...HEAD`

Include:
- Summary of changes
- Why these changes were made
- Testing done
- Any breaking changes
```

### Code Review

```markdown
---
description: "Review recent changes"
agent: plan
---

Review the recent changes for issues:

!`git diff HEAD~3`

Check for:
- Bugs and logic errors
- Security vulnerabilities
- Performance issues
- Code style violations
```

### Documentation Generator

```markdown
---
description: "Generate docs for file"
---

Generate documentation for @$1

Include:
- Module overview
- Function/method documentation
- Usage examples
- Any important notes
```

Usage: `/docs src/utils/helpers.ts`

### Dependency Update

```markdown
---
description: "Check and update dependencies"
agent: build
---

Current dependencies:
!`npm outdated`

Review outdated packages and:
1. Identify breaking changes
2. Update safely
3. Run tests to verify
```

### Commit Message

```markdown
---
description: "Generate commit message"
---

Changes to commit:
!`git diff --staged`

Generate a conventional commit message:
- feat: for new features
- fix: for bug fixes
- docs: for documentation
- refactor: for code changes
- test: for tests
```

## Advanced Usage

### Chaining Commands

Commands can be used in sequence:

```bash
/test           # Run tests
/review         # Review any issues
/commit         # Generate commit message
```

### With Agents

Specify agent for specialized handling:

```markdown
---
description: "Security audit"
agent: security-auditor
---

Perform a security audit on this codebase.
```

### Subtask Mode

Force subagent execution to avoid polluting main context:

```markdown
---
description: "Research topic"
subtask: true
---

Research $ARGUMENTS and provide a summary.
```

## Built-in Commands

Cortex includes several built-in commands:

| Command | Description |
|---------|-------------|
| `/help` | Show available commands |
| `/model` | Change AI model |
| `/agent` | Switch agent |
| `/clear` | Clear conversation |
| `/compact` | Compact history |
| `/edit` | Edit a file |
| `/undo` | Undo last change |
| `/redo` | Redo undone change |
| `/diff` | Show file changes |
| `/share` | Share session |
| `/init` | Initialize project |

Custom commands override built-in commands with the same name.

## Command Locations

| Location | Scope |
|----------|-------|
| `.cortex/commands/` | Project |
| `~/.cortex/commands/` | Personal |
| `config.toml` | Global |

Project commands take precedence over personal commands.

## Best Practices

<AccordionGroup>
  <Accordion title="Keep Commands Focused">
    Each command should do one thing well:
    ```markdown
    ---
    description: "Run unit tests"
    ---
    Run unit tests with coverage.
    ```
  </Accordion>
  
  <Accordion title="Use Descriptive Names">
    Name commands by what they do:
    - `/test` - Run tests
    - `/review` - Code review
    - `/docs` - Generate docs
  </Accordion>
  
  <Accordion title="Document Arguments">
    Make argument usage clear:
    ```markdown
    ---
    description: "Create component: /component <name> [dir]"
    ---
    ```
  </Accordion>
  
  <Accordion title="Choose Appropriate Agents">
    Use specialized agents for specific tasks:
    - `plan` for analysis (read-only)
    - `build` for modifications
    - Custom agents for specialized tasks
  </Accordion>
</AccordionGroup>
