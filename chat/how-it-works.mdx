A Chat turn is a real tool loop: the model emits tool calls, the API executes them, results re-enter the context, the loop continues until the model stops or hits Chat's round budget.

## What you see

1. You send a message, with optional Library attachments.
2. Tokens stream. Tools may run. Results come back into the thread.
3. The model stops, or Chat hits eight tool rounds. That budget is Chat-only — do not copy it onto Code or Bot.

## Tools the model can receive

`python`, `web_search`, `web_extract`, `current_time`, `skill_view`, canvas, memory, `generate_image`, `detect_image`, `read_artifact` / `grep_artifact`, `design_write` / `design_read`, plus Chat-enabled plugins and the owner's MCP servers.

Chat's Python tool is a small snippet sandbox. It is not Code's workspace shell or Bot's computer.

## Compaction

Compaction runs on the request path and fails closed. It keeps the last user ask, the active research plan, open artifact ids, and research child ids. A summariser outage is `service_unavailable`, not a silent drop of old turns.

English system prompt. No competitor product names.
