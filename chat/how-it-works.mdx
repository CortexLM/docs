---
title: "How Chat works"
description: "One function-calling loop, compaction that fails closed."
---

A Chat turn is a real tool loop: the model emits tool calls, the API executes
them, results re-enter the context, the loop continues until the model stops
or hits Chat's round budget (`CHAT_MAX_TOOL_ROUNDS = 8`). Do not copy that
budget onto Code or Bot.

**Catalog the model receives:** `python`, `web_search`, `web_extract`,
`current_time`, `skill_view`, canvas, memory, `generate_image`, `detect_image`,
`read_artifact` / `grep_artifact`, `design_write` / `design_read`, plus Chat-enabled
plugins and the owner's MCP servers.

**Compaction** runs on the request path and fails closed. Anchors: the last
user ask, the active research plan, open `art_…` ids, research child ids.
A summariser outage is `service_unavailable`, not a silent drop of old turns.

English system prompt. No competitor product names.
