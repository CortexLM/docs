# cortex github

Manage GitHub Actions integration for automated PR reviews, issue triage, and CI/CD automation.

## Usage

```bash
cortex github <SUBCOMMAND>
```

## Subcommands

| Command | Description |
|---------|-------------|
| `install` | Install GitHub Actions workflow |
| `run` | Run GitHub agent in Actions context |
| `status` | Check installation status |

---

## cortex github install

Install the GitHub Actions workflow for Cortex automation.

### Usage

```bash
cortex github install [OPTIONS]
```

### Examples

```bash
# Install with defaults
cortex github install

# Install in specific directory
cortex github install --path /path/to/repo

# Force overwrite existing
cortex github install --force

# Custom workflow name
cortex github install --workflow-name "CortexAI"

# Disable PR review
cortex github install --pr-review=false
```

### Options

| Flag | Short | Description | Default |
|------|-------|-------------|---------|
| `--path` | `-p` | Repository root path | Current directory |
| `--force` | `-f` | Overwrite existing workflow | `false` |
| `--pr-review` | | Enable PR review automation | `true` |
| `--issue-automation` | | Enable issue automation | `true` |
| `--workflow-name` | | Custom workflow name | `Cortex` |

### Generated Workflow

The command creates `.github/workflows/Cortex.yml`:

```yaml
name: Cortex
on:
  issue_comment:
    types: [created]
  pull_request:
    types: [opened, synchronize, reopened]
  issues:
    types: [opened]

jobs:
  cortex:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install Cortex
        run: curl -fsSL https://cortex.foundation/install | bash
      - name: Run Cortex Agent
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          CORTEX_API_KEY: ${{ secrets.CORTEX_API_KEY }}
        run: |
          cortex github run \
            --event ${{ github.event_name }} \
            --token ${{ secrets.GITHUB_TOKEN }} \
            --event-path ${{ github.event_path }} \
            --repository ${{ github.repository }}
```

## cortex github run

Run the GitHub agent in an Actions context. This is typically called from the workflow.

### Usage

```bash
cortex github run [OPTIONS]
```

### Options

| Flag | Short | Description |
|------|-------|-------------|
| `--event` | `-e` | GitHub event type (required) |
| `--token` | `-t` | GitHub token |
| `--event-path` | | Path to event payload JSON |
| `--repository` | | Repository in owner/repo format |
| `--run-id` | | GitHub run ID |
| `--dry-run` | | Show what would happen without executing |

### Supported Events

| Event | Trigger | Actions |
|-------|---------|---------|
| `issue_comment` | Comment on issue/PR | Respond to commands |
| `pull_request` | PR opened/updated | Welcome, review |
| `pull_request_review` | PR review submitted | Respond to feedback |
| `issues` | Issue opened | Greet, triage |

|------|-------|-------------|

## Setup Guide

### Step 1: Install Workflow

```bash
cd your-repo
cortex github install
```

### Step 2: Add Secrets

In your GitHub repository:
1. Go to **Settings** → **Secrets and variables** → **Actions**
2. Add `CORTEX_API_KEY` with your Anthropic/OpenAI API key

### Step 3: Commit and Push

```bash
git add .github/workflows/Cortex.yml
git commit -m "Add Cortex CI/CD automation"
git push
```

### Step 4: Test

Create a new issue or PR and comment `/cortex help`.

Users can interact with Cortex by commenting on issues and PRs:

| Command | Description |
|---------|-------------|
| `/cortex help` | Show available commands |

## Features

### PR Review Automation

When enabled, Cortex:
- Welcomes new contributors
- Reviews code for bugs, security, best practices
- Responds to review comments

```yaml
# Trigger events
pull_request:
  types: [opened, synchronize, reopened]
```

### Issue Automation

When enabled, Cortex:
- Greets new issue authors
- Provides initial analysis
- Suggests relevant documentation

```yaml
# Trigger events
issues:
  types: [opened]
```

### Comment Commands

Respond to commands in any issue or PR comment:

```yaml
# Trigger events
issue_comment:
  types: [created]
```

## Configuration

### Custom Triggers

Modify the workflow to add custom triggers:

```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened]
    paths:
      - 'src/**'  # Only trigger for src changes
```

### Custom Model

Use a specific model for GitHub actions:

```yaml
- name: Run Cortex Agent
  env:
    CORTEX_MODEL: gpt-4o
  run: cortex github run ...
```

### Autonomy Level

Control what Cortex can do:

```yaml
- name: Run Cortex Agent
  run: |
    cortex exec --auto read-only \
      "Review the changes in this PR"
```

## Security

<AccordionGroup>
  <Accordion title="Protecting Secrets">
    - Never commit API keys
    - Use GitHub Secrets for all sensitive data
    - Rotate keys periodically
  </Accordion>
  
  <Accordion title="Limiting Permissions">
    The default `GITHUB_TOKEN` has limited permissions. For additional access:
    
    ```yaml
    permissions:
      contents: read
      pull-requests: write
      issues: write
    ```
  </Accordion>
  
  <Accordion title="Branch Protection">
    Enable branch protection rules to prevent direct pushes and require reviews.
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Workflow Not Triggering">
    1. Check if workflow file is in `.github/workflows/`
    2. Verify event types match your action
    3. Check workflow syntax with `yamllint`
  </Accordion>
  
  <Accordion title="API Key Errors">
    1. Verify `CORTEX_API_KEY` is set in repository secrets
    2. Check if key has correct permissions
    3. Test key locally: `cortex login status`
  </Accordion>
  
  <Accordion title="Rate Limiting">
    GitHub has rate limits for API calls. For high-volume repos:
    - Use caching
    - Batch operations
    - Consider GitHub Apps for higher limits
  </Accordion>
</AccordionGroup>
