# cortex run

Run Cortex in non-interactive mode by passing a prompt directly. Useful for scripting, automation, or when you want a quick answer without launching the full TUI.

## Usage

```bash
cortex run [OPTIONS] [MESSAGE...]
```

## Examples

```bash
# Basic usage
cortex run "Explain how closures work in Rust"

# With model override
cortex run --model gpt-4o "Review this code for security issues"

# Continue a session
cortex run --continue "Now add error handling"

# Attach files
cortex run --file src/main.rs "Explain this file"

# Stream output
cortex run --stream "Generate a long explanation"

# Copy result to clipboard
cortex run --copy "Write a commit message for recent changes"

# JSON output for scripting
cortex run --format json "List all functions in this file"
```

## Options

### Message & Input

| Flag | Short | Description |
|------|-------|-------------|
| `MESSAGE...` | | The prompt message (multiple words joined with spaces) |
| `--command` | | Execute a predefined command instead of a prompt |
| `--file` | `-f` | Attach file(s) to the message (can be repeated) |

### Session Management

| Flag | Short | Description |
|------|-------|-------------|
| `--continue` | `-c` | Continue the most recent session |
| `--session` | `-s` | Specify a session ID to continue |
| `--title` | | Title for the new session |
| `--share` | | Auto-share the session and print URL |

### Model & Agent

| Flag | Short | Description | Default |
|------|-------|-------------|---------|
| `--model` | `-m` | Model in provider/model format | Config default |
| `--agent` | | Agent to use for this request | |

### Output Control

| Flag | Short | Description | Default |
|------|-------|-------------|---------|
| `--format` | | Output format: default, json, jsonl | `default` |
| `--stream` | | Stream output as it arrives | `true` |
| `--copy` | `-C` | Copy final response to clipboard | `false` |
| `--notification` | `-n` | Send desktop notification on completion | `false` |
| `--verbose` | `-v` | Enable verbose/debug output | `false` |

### Model Parameters

| Flag | Short | Description | Range |
|------|-------|-------------|-------|
| `--temperature` | `-t` | Model temperature | 0.0-2.0 |
| `--top-p` | | Top-p sampling parameter | 0.0-1.0 |
| `--seed` | | Random seed for reproducibility | |

### Server & Advanced

| Flag | Description |
|------|-------------|
| `--attach` | Attach to a running Cortex server URL |
| `--port` | Port for local server (defaults to random) |
| `--cwd` | Working directory override |
| `--timeout` | Timeout in seconds (0 for no timeout) |

## Output Formats

### Default (Formatted)

Human-readable output with colors and formatting:

```bash
cortex run "explain main.rs"
```

### JSON

Structured output with final result:

```bash
cortex run --format json "explain main.rs"
```

Output:
```json
{
  "type": "result",
  "session_id": "abc123",
  "message": "The main.rs file contains...",
  "events": 5,
  "success": true
}
```

### JSONL (JSON Lines)

Streaming events, one JSON object per line:

```bash
cortex run --format jsonl "explain main.rs"
```

Each line is a separate event:
```json
{"event_id": 1, "session_id": "abc123", "event": {...}}
{"event_id": 2, "session_id": "abc123", "event": {...}}
```

## Piping Input

Read prompt from stdin:

```bash
# Pipe file content
cat error.log | cortex run "explain these errors"

# Pipe command output
git diff | cortex run "summarize these changes"

# Combine with arguments
echo "function code here" | cortex run "optimize this function"
```

## File Attachments

Attach files to provide context:

```bash
# Single file
cortex run --file src/main.rs "explain this code"

# Multiple files
cortex run --file src/main.rs --file src/lib.rs "how do these connect?"

# With images (for vision models)
cortex run --file screenshot.png "describe this UI"
```

Supported formats:
- **Code**: `.rs`, `.py`, `.js`, `.ts`, `.go`, `.java`, etc.
- **Documents**: `.md`, `.txt`, `.json`, `.yaml`, `.toml`
- **Images**: `.png`, `.jpg`, `.gif`, `.webp` (for vision-capable models)

## Session Continuation

Continue previous conversations:

```bash
# Start a session
cortex run --title "refactoring" "analyze the user module"

# Continue the same session
cortex run --continue "now refactor it to use dependency injection"

# Or specify session ID
cortex run --session abc123 "add error handling"
```

## Custom Commands

Execute predefined commands from your config:

```bash
# Define in config.toml or .cortex/commands/
cortex run --command test "src/user.rs"
```

This expands the `test` command template with the provided arguments.

## Server Attachment

Attach to a running server to avoid cold start:

```bash
# Start server in background
cortex serve &

# Run commands against it
cortex run --attach http://localhost:3000 "explain this code"
```

This is useful for:
- Faster response times (no MCP server cold boot)
- Shared context across commands
- Long-running sessions

## Desktop Notifications

Get notified when long tasks complete:

```bash
cortex run --notification "run the full test suite and report"
```

Works on:
- **macOS**: Native notification center
- **Linux**: notify-send
- **Windows**: PowerShell toast notifications

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | Error (task failed, API error, etc.) |
| 130 | Interrupted (Ctrl+C) |

| Variable | Description |
|----------|-------------|

| `CORTEX_API_KEY` | API key for authentication |
